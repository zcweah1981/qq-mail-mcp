# 推广执行方案

定位：面向使用 Codex 的中文开发者，提供 QQ 邮箱只读查询。重点是可复现安装、清楚的权限边界和真实验证范围，不使用官方认可、全平台兼容或完全隐私宣传。

## 本轮可执行：GitHub 基础

- 保持首屏中文定位、三步 Windows 安装入口、明确标注的流程示意及支持矩阵。
- 设置准确的 About 与发现 topics，不更改仓库可见性或用户服务权限。
- 提供贡献指南、脱敏问题模板、私密安全报告入口。
- 完整测试与独立审查后，创建 v0.1.0 早期 GitHub Release，使用 prerelease 标识，避免成熟生产版暗示。
- 核对公开文件、main SHA 与 Release 目标；仅发布仓库功能文档，不发布未审阅文章。

## 反馈阶段

用户审阅中文主稿后选择合适的技术博客或公众号，重点展示安装与只读场景。此前 V2EX 草稿不用于发帖；该渠道应由用户本人根据事实原创，并在发布前核对当前规则。没有自动发送或定时推广任务。

收集匿名、合成的安装反馈：系统版本、安装失败原因、首次状态检查结果、问题复现率。以解决问题为目标，不预设星数或增长结果，不收集邮件或凭据。

## 社区与官方目录：独立门槛

社区目录需分别核对当前政策与前置验证。不能伪造徽章或用不存在的 Docker/托管环境满足申请。目录联系信息由用户自行决定，未授权前不提交邮箱或表单。提交申请不代表收录。

[官方目录路线](DISTRIBUTION.md)另有技术与第三方非官方连接器资格障碍。当前只发布本地版，不为营销扩建公网 HTTP，不提交官方申请，不发布 npm。

## 直接 GitHub marketplace 的评估

官方 Codex 支持添加 GitHub marketplace，但本仓库当前 .mcp.json 仍为路径模板；现有安装器负责安装依赖并生成私有本地适配器。直接注册本仓库缺少可运行适配路径及缓存依赖初始化，因此不发布未经验证的两条安装命令。当前唯一推荐路线仍是 README 的 install.ps1。将来简化时必须先在隔离配置证明安装与安全启动行为，而不是只添加 catalog 文件。
